# Benchmarking Reasoning Robustness in Large Language Models

- Year: 2025
- Venue: arXiv
- Authors: Tong Yu; Yongcheng Jing; Xikun Zhang; Wentao Jiang; Wenjie Wu; Yingjie Wang; Wenbin Hu; Bo Du; Dacheng Tao
- URL: https://arxiv.org/abs/2503.04550
- BibTeX key (if we add it): yu2025mathrob
- Tags: robustness, reasoning, benchmark, math

## One-sentence takeaway

Math-RoB proposes a robustness-oriented math reasoning benchmark that perturbs problems to expose LLM brittleness (position bias, instruction sensitivity, numerical fragility, and hallucinated completion under missing info).

## What problem does it solve?

- Standard math-reasoning benchmarks can overestimate “reasoning” by rewarding pattern-matching / memorization; this work targets *robustness* failures that appear under small but realistic perturbations (long mixed inputs, extra instructions, symbol/number substitution, missing critical info).

## What is the core method / protocol?

- Introduces **Math-RoB** benchmark suite with four datasets designed around four “robustness issues”:
  - **Math-RoB-RoLo**: long mixed input robustness by concatenating multiple Math500 questions (q1/q2/q3) and instructing the model to answer only one.
  - **Math-RoB-Define**: operator-substitution tasks where operators are redefined (plus optional one-shot example) to test instruction sensitivity / multi-replacement fidelity.
  - **Math-RoB-Number**: replace numeric values with symbols (Greek letters mapped to numbers) to stress multi-step reasoning beyond surface patterns.
  - **Math-RoB-Delete**: remove key information to test whether models detect incompleteness or “fill in” missing values (hallucinated completion).
- Source base: **Math500**; additionally, a small curated set of ~40 “change questions” (generated by multiple LLMs and manually verified by answer consensus) is used to derive Define/Number/Delete variants.
- Evaluation uses Accuracy + Drop Rate across variants; introduces a metric for missing-info completion behavior:
  - **Memory Completion Rate (MCR)**: fraction of samples where the model completes missing critical data in its first generation.
- (Tooling in experiments) They also study CoT augmented with **process-supervised reward models (PRMs)** and search (MCTS with width 5) plus voting schemes (e.g., majority/min/last/minmax/lastmax) to improve performance.

## What are the key metrics?

- Accuracy (AR) on each dataset.
- Drop Rate between source and perturbed dataset(s).
- Memory Completion Rate (MCR) on Delete-style missing-information questions (measures “gap filling” behavior rather than correctness).

## What are the main results?

- Across 12 models (open + API), performance often drops under perturbations even when the perturbed questions are close to training-like distributions.
- Long mixed inputs (RoLo): smaller models show larger degradation; larger models (e.g., GPT-4o, Kimi, DeepSeek-V3) are more robust but still drop.
- Operator/number substitutions: multi-replacement instruction-following remains a failure mode for smaller (<~8B) models; one-shot prompting helps but doesn’t eliminate brittleness.
- Missing information (Delete): models frequently **fill in missing critical values** rather than flagging incompleteness; authors interpret this as memorization-driven behavior / leakage susceptibility.

## How is this similar to GALILEO?

- Both care about *robustness/generalization* rather than raw in-distribution accuracy.
- The idea of creating controlled perturbations/variants to reveal brittle behaviors aligns with stress-testing pipelines (e.g., invariance checks, counterfactual inputs).

## How is this different from GALILEO?

- Domain/task: Math-RoB is specific to mathematical reasoning question-answering and instruction-following under synthetic perturbations; GALILEO may target broader scientific reasoning / agentic evaluation (depending on our framing) rather than operator-symbol games.
- The benchmark is relatively small in some components (e.g., 40-question derivative set) and is not an end-to-end system evaluation.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO already has principled robustness desiderata (e.g., explicit uncertainty / abstention, calibrated failure detection, or formal invariances), we can claim stronger grounding than “observe drop rates and hallucinated completion”.

## Where GALILEO is weaker / needs to improve

- If GALILEO lacks explicit tests for (a) long multi-query positional confusion, (b) sensitivity to harmless instruction paraphrases, or (c) missing-information handling/abstention, this paper’s taxonomy is a useful checklist.
