# DeepDialogue: A Multi-Turn Emotionally-Rich Spoken Dialogue Dataset

- Year: 2025
- Venue: arXiv
- Authors: Alkis Koudounas; Moreno La Quatra; Elena Baralis
- URL: https://arxiv.org/abs/2505.19978
- BibTeX key (if we add it): deepdialogue2025
- Tags: multi-turn, dataset, spoken-dialogue, emotion

## One-sentence takeaway

DeepDialogue is a large-scale multi-turn dialogue dataset with explicit emotion trajectories and paired synthetic speech, built by cross-LLM conversation generation plus human+LLM filtering, and it surfaces a clear “turn-length breakdown” for smaller models.

## What problem does it solve?

- Existing multi-turn dialogue datasets are often (a) text-only, (b) shallow in turns, (c) narrow in domains, and/or (d) missing emotion labels/progression, which limits studying long-horizon conversational coherence and affect.
- Need data that stresses multi-turn consistency (topic + persona + emotion) and supports multimodal (text+speech) research.

## What is the core method / protocol?

- Generate dialogues conditioned on:
  - a domain (41 domains)
  - an “emotional chain” (emotion progression across turns; 20 emotions)
  - a target length (3–10 turns)
- Use 9 different LMs (reported range ~4B–72B) and *pair models* to create initial conversations (65,600).
- Quality control:
  - Human evaluation on a subset (reported: 984 dialogues, 3 annotators)
  - LLM-based automated filtering aligned to human preferences → retain 40,150 “high-quality” dialogues.
- Speech synthesis for the whole corpus (two variants):
  - XTTS-style approach with explicit emotion conditioning via reference audio samples (aim: emotion-consistent voice + consistent speaker identity)
  - Orpheus-style approach without explicit emotion control (emotion inferred implicitly from text cues)

## What are the key metrics?

- Dataset stats: #dialogues, #turns, domain coverage, emotion coverage, and availability of audio.
- Quality/coherence analyses as a function of:
  - model size (small vs large)
  - turn depth (notably >6 turns)
  - domain type (concrete vs abstract)
  - same-model vs cross-model pairing (“cross-model effect”)

## What are the main results?

- Scale/coverage: 40,150 dialogues; 241,825 turns; 41 domains; 20 emotions; speech version reported at ~488 hours.
- Multi-turn degradation: smaller models reportedly fail to maintain coherence beyond ~6 turns (instruction following / emotion consistency / domain adherence deteriorate).
- Domain effect: concrete domains yield more grounded/meaningful conversations than abstract domains.
- Cross-model effect: dialogues generated by *different* models are more coherent than self-chat (same-model) dialogues.

## How is this similar to GALILEO?

- Provides a setting where “multi-turn failure” can be operationalized as a *turn-of-failure* phenomenon (coherence/emotion drift vs staying on-track), which is adjacent to long-horizon robustness evaluation.
- Emphasizes controlled generation (domain + emotional trajectory), which is analogous to GALILEO-style controlled interventions/conditions.

## How is this different from GALILEO?

- Primary objective is a *dialogue dataset + multimodal speech synthesis*, not an evaluation protocol focused on truthfulness, susceptibility, or safety-relevant drift.
- Labels are about emotion progression and domain constraints rather than (e.g.) belief revision vs drift, pressure compliance, or deception.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO targets safety-relevant multi-turn instability (e.g., pressure, sycophancy, belief drift), it likely has clearer causal manipulations and outcome measures tied to “incorrectness/unsafe behavior,” which DeepDialogue does not directly define.

## Where GALILEO is weaker / needs to improve

- If GALILEO is text-only, DeepDialogue highlights a path to evaluating robustness in *spoken* interactions (prosody/emotion as an additional control channel).
- DeepDialogue’s explicit emotion chains suggest richer control conditions for studying when/why models drift across turns.

## Action items for GALILEO (experiments / method / writing)

- [ ] Consider adding an “affective load” control: run the same multi-turn robustness tests under different emotion trajectories (e.g., escalating frustration) to measure whether failure rates shift.
- [ ] Add a reporting slice by turn index (e.g., survival-style curves): DeepDialogue’s “>6 turns” observation is a strong motivation for turn-depth stratification.
- [ ] Consider cross-model generation for synthetic test dialogues: seed prompts and let different model families interact to increase diversity/coherence of generated multi-turn contexts.
