# LUMINA: Long-horizon Understanding for Multi-turn Interactive Agents

- Year: 2026
- Venue: arXiv

- URL: https://arxiv.org/abs/2601.16649
- BibTeX key (if we add it): lumina2026
- Tags: multi-turn, agents, long-horizon, planning, state-tracking, oracle-interventions, robustness

## One-sentence takeaway

LUMINA proposes an “oracle counterfactual” evaluation framework (perfect planning / perfect state tracking / history pruning) in controlled procedurally-generated multi-turn tasks to identify which missing skills bottleneck long-horizon agent success.

## What problem does it solve?

- Multi-turn, long-horizon agent benchmarks show low end-to-end success, but it’s unclear *which underlying capability* (planning vs state tracking vs handling long context, etc.) is the limiting factor.
- Real-world agent benchmarks make “skill ablations” hard because there are many plausible trajectories and you can’t cheaply annotate what an oracle would do at every step.

## What is the core method / protocol?

- Introduces an **oracle intervention / counterfactual** framework:
  - Ask: *how would the agent perform if it had an oracle that perfectly provided some skill*?
  - Measure delta in end-to-end task success under each oracle.
- Uses **procedurally-generated, game-like environments** where optimal actions can be computed at each state, enabling precise oracle assistance:
  - **ListWorld**: mutate a Python list using only `pop` actions (tests careful state manipulation).
  - **TreeWorld**: find a node in a tree using only `get_children` actions (tests exploration / tracking).
  - **GridWorld**: navigate a 2D grid to target avoiding holes (tests planning + state).
- Oracle types studied (and combinations):
  - **Planning oracle**: provides a description of a single-turn subtask on an optimal trajectory.
  - **State tracking oracle**: provides accurate current state.
  - **History pruning oracle**: rewrites context to remove distractors / compress history.

## What are the key metrics?

- **Task success rate** over full multi-turn episodes (long-horizon completion).
- **Per-step accuracy** (whether chosen action is among optimal actions).
- Analysis by task complexity and model size; compares gap between step accuracy and end-to-end success to diagnose **compounding error**.

## What are the main results?

- Reports a notable **disconnect**: agents can have relatively high per-step optimal-action accuracy yet still achieve low overall success on long trajectories → **small error rates compound**.
- Oracle interventions generally **improve success**, but:
  - gains vary by **model size** and **environment**;
  - some skills help consistently (planning is highlighted in the abstract), while others are more conditional.
- Takeaway: progress on long-horizon agents likely needs **environment- and model-specific** improvements rather than assuming one universal bottleneck.

## How is this similar to GALILEO?

- Both are about **multi-turn / long-horizon failures** and diagnosing why systems degrade over turns.
- The “step accuracy vs episode success” lens aligns with GALILEO’s emphasis on **trajectory-level robustness** rather than single-turn scores.
- The notion of **counterfactual evaluation** (what if one capability were fixed) is conceptually close to controlled analyses of failure modes.

## How is this different from GALILEO?

- LUMINA focuses on **procedurally-generated environments** with explicit oracle interventions; it is less about real conversational settings (social pressure, persuasion, sycophancy) and more about *agentic control* and state.
- The primary evaluation is **task success / optimal-action accuracy**, not preference drift / belief instability / user influence.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO targets *realistic* conversational robustness (user pressure, rebuttals, misinformation, value drift), it may provide **higher ecological validity** than game-like environments.
- GALILEO can potentially unify multiple instability types (belief/stance/moral/safety) under a single evaluation story.

## Where GALILEO is weaker / needs to improve

- LUMINA’s oracle framework is a strong template for **attributing failures to missing sub-skills**; if GALILEO lacks similarly clean counterfactuals, it may be harder to make causal claims.
- GALILEO might benefit from more **controlled synthetic environments** to isolate mechanisms (planning vs tracking vs context handling).
