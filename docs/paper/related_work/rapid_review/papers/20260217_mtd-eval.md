# Learning an Efficient Multi-Turn Dialogue Evaluator from Multiple LLM Judges

- Year: 2025
- Venue: arXiv
- Authors: Yuqi Tang; Kehua Feng; Yunfeng Wang; Zhiwen Chen; Chengfei Lv; Gang Yu; Qiang Zhang; Keyan Ding; Huajun Chen
- URL: https://arxiv.org/abs/2508.00454
- BibTeX key (if we add it): Tang2025MTDEval
- Tags: multi-turn, evaluation, llm-judges, preference-modeling, robustness

## One-sentence takeaway

Distills *multiple* LLM-judge pairwise preferences into a single lightweight multi-turn dialogue evaluator (MTDEval) by jointly learning dialogue-quality scoring and per-judge reliability, reducing inference cost versus “jury-of-LLMs” while improving robustness.

## What problem does it solve?

- Multi-turn dialogue evaluation via “LLM-as-a-judge” is biased/unstable (prompt sensitivity, self-preference, score compression).
- Using multiple judges + aggregation helps but is expensive at inference (many model calls per evaluation).
- Open-source learned evaluators trained from a *single* judge inherit that judge’s biases and underperform.

## What is the core method / protocol?

- **Data**: Build a multi-judge pairwise preference dataset **P2-MTD** (≈11K multi-turn dialogue pairs) from Multiturn-Chat-0.8M (Chinese).
  - 5 judges: Claude-3.7-Sonnet, GPT-4o, Grok-3, DeepSeek-R1, Gemini-2.0-Flash.
  - 3-way label per dimension: A / B / Fair.
  - **10 fine-grained dimensions** + overall: Accuracy, Logicality, Conversationality, Relevance, Personalization, Creativity, Interactivity, Emotionality, Informativeness, Safety.
- **Model**: **MTDEval** = frozen text-embedding LLM (Llama-3-8B initialized from a reward model) + small MLP scoring heads (K-dim + overall).
- **Learning**: Learning-to-rank with a probabilistic pairwise preference model (Thurstone Case V / probit-like) and **jointly learned judge reliabilities** per dimension:
  - Sensitivity (hit rate) α and specificity (correct rejection) β for each judge; “Fair” labels excluded from α/β updates.
  - Optimize via maximum likelihood (NLL) over all pairs/dimensions.
- **Benchmarks**: Evaluate for (i) single rating correlation, (ii) pairwise preference accuracy (with/without ties), and (iii) multi-dimensional preference accuracy.
- **Extra resource**: **Daily-MTD**: 600 human-annotated multi-turn dialogues (daily-life), with overall ratings + pairwise + dimension-level labels.

## What are the key metrics?

- Single-rating: Pearson/Spearman correlation vs human ratings.
- Pairwise: accuracy w/o ties and w/ ties (ternary incl. Fair).
- Multi-dimensional: dimension-level preference accuracy (averaged across 10 dimensions).
- Efficiency: runtime per instance (reported relative to autoregressive judge baselines).

## What are the main results?

- MTDEval beats open-source evaluator baselines on 3 single-rating and 4 pairwise benchmarks, and is competitive with (sometimes better than) proprietary LLM judges on some datasets.
- Training on **multi-judge** preferences outperforms training on any **single** judge’s annotations (ablation).
- Learned α/β parameters rank judges by effective reliability (e.g., DeepSeek-R1 strongest in their analysis).
- Encoder-style scorer yields substantially lower inference latency than autoregressive LLM-as-judge baselines.

## How is this similar to GALILEO?

- Same high-level motivation: **evaluation under multi-turn interaction** is brittle; naive single-judge scoring can be biased.
- Treats multi-turn dialogue quality as multi-dimensional and benefits from **paired / comparative** signals.
- Provides a concrete example of **aggregating multiple judges** and modeling judge reliability—relevant if GALILEO uses LLM-judge evaluation anywhere.

## How is this different from GALILEO?

- Focus is *evaluation model construction* (distilling judges), not measuring **belief drift vs evidence-driven revision** under social pressure.
- Targets general dialogue quality dimensions (incl. Safety) rather than explicit pressure operators, time-to-failure, flip/recovery trajectories.
- Their training data is largely daily-life multi-turn dialogues (plus standard eval sets), not adversarial persuasion / peer pressure protocols.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO has explicit **neutral vs pressure** controls and tracks **flip timing / recovery**, it offers clearer causal attribution than a generic “dialogue quality” evaluator.
- GALILEO’s focus on robustness dynamics can be more directly aligned with failure-under-pressure claims than correlation/accuracy metrics for evaluation.

## Where GALILEO is weaker / needs to improve

- If GALILEO relies on single LLM judges (or a single rubric prompt), this paper is a warning: judge bias can dominate conclusions.
- GALILEO may need a more explicit plan for **judge aggregation** or **judge reliability calibration** if evaluation depends on LLM judgments.
