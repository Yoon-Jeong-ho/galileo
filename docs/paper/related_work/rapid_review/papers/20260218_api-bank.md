# API-Bank: A Comprehensive Benchmark for Tool-Augmented LLMs

- Year: 2023
- Venue: EMNLP 2023
- Authors: Minghao Li, Yingxiu Zhao, Bowen Yu, Feifan Song, Hangyu Li, Haiyang Yu, Zhoujun Li, Fei Huang, Yongbin Li
- URL: https://arxiv.org/abs/2304.08244
- BibTeX key (if we add it): Li2023APIBank
- Tags: tool-use, benchmark, api-calling, agents

## One-sentence takeaway

API-Bank provides an executable benchmark + training data for tool-augmented LLMs, decomposing tool use into call / retrieve+call / plan+retrieve+call and showing large gaps between GPT-4 and smaller/fine-tuned models.

## What problem does it solve?

- Lack of *runnable* and *authentic* evaluation benchmarks to measure how well LLMs can use external tools/APIs (beyond static text matching), and lack of large-scale tool-use training data.

## What is the core method / protocol?

- Benchmark + evaluation harness with a pool of APIs and executable calls.
- Ability taxonomy (driven by user interviews) into three graded settings:
  - **Call**: APIs are known/provided; model must select and call correctly.
  - **Retrieval+Call**: many APIs exist; model must retrieve relevant API then call.
  - **Plan+Retrieval+Call**: multi-step tool use where model must plan and execute multiple calls.
- Data:
  - Evaluation set: **73** API tools; **314** tool-use dialogues; **753** API calls (manually annotated).
  - Training set: **1,888** dialogues from **2,138** APIs across **1,000** domains; generated via a **multi-agent** LLM pipeline to reduce annotation cost (reported 98% reduction).
- Model contribution: fine-tune Alpaca-7B → **Lynx** (tool-augmented).

## What are the key metrics?

- Task accuracy / success on executable API calling under the three ability conditions (call vs retrieval+call vs plan+retrieval+call).
- Error analysis categories (planning/retrieval/calling failures).

## What are the main results?

- GPT-3.5 improves over GPT-3 in tool utilization; GPT-4 is strongest in planning.
- **Lynx** improves Alpaca by **>26 pts** on tool-use performance (paper reports) and approaches GPT-3.5, but still lags GPT-4 substantially.
- Smaller open models show some API call accuracy (~20% reported) but near-zero retrieval/planning ability.

## How is this similar to GALILEO?

- Both emphasize **multi-step capabilities** rather than single-turn accuracy, and propose more *operational* evaluation protocols (not purely subjective scoring).
- The **ability decomposition** idea (separating distinct failure modes) parallels GALILEO’s use of staged metrics (survival/turn-of-failure/recovery) to diagnose weaknesses.

## How is this different from GALILEO?

- API-Bank targets **tool-use / agentic API interaction** (planning + retrieval + API-call correctness) in an executable environment.
- GALILEO targets **belief-consistency under multi-turn social pressure** (persona-induced flips) and **recovery** on *ground-truth* tasks; no external tools are involved.

## Where GALILEO is stronger / cleaner (if true)

- Uses **ground-truth answer checking** for multi-turn persuasion dynamics (clear success criterion), whereas tool-use can entangle retrieval/tool availability and environment specifics.
- Measures *when* a model fails (turn-of-failure) and whether it can recover—axes not central in API-Bank.

## Where GALILEO is weaker / needs to improve

- Does not cover **tool-augmented agent settings**; if GALILEO claims breadth in “multi-turn robustness”, it should clarify that tool-use is out-of-scope (or add an extension).
