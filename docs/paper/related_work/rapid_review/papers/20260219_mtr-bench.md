# MTR-Bench: A Comprehensive Benchmark for Multi-Turn Reasoning Evaluation

- Year: 2025
- Venue: arXiv
- Authors: Xiaoyuan Li; Keqin Bao; Yubo Ma; Moxin Li; Wenjie Wang; Rui Men; Yichang Zhang; Fuli Feng; Dayiheng Liu; Junyang Lin
- URL: https://arxiv.org/html/2505.17123v1
- BibTeX key (if we add it): mtrbench2025li
- Tags: multi-turn, interactive-eval, reasoning, benchmark, automated-evaluation

## One-sentence takeaway

MTR-Bench proposes an automated, scalable benchmark to measure LLM reasoning in interactive multi-turn environments (not just single-shot QA), showing frontier “reasoning” models still struggle as difficulty/turns grow.

## What problem does it solve?

- Existing reasoning evals are largely single-turn (math/logic/commonsense/code) and miss the iterative, feedback-driven nature of real problem solving.
- Prior multi-turn benchmarks either emphasize dialogue quality (e.g., MT-Bench) or are narrow and expensive due to human-in-the-loop evaluation (e.g., game-style arenas).
- Need (a) diverse multi-turn tasks and (b) a fully automated evaluation protocol that can scale and avoid quick saturation.

## What is the core method / protocol?

- Benchmark: 4 task classes, 40 tasks total, each with 3 difficulty levels; 30 instances per (task,difficulty) → 3,600 total instances.
- Four interactive task classes:
  - Information Probing (hidden but fixed info; query to reveal clues)
  - Dynamic Adaptation (target state changes deterministically after wrong attempts)
  - State Operation (hidden mechanics/control; infer mechanism from feedback)
  - Strategic Gaming (two-player/adversarial environment; outcome depends on interaction)
- Automated framework with three components:
  - Generator: instantiates a task template at a chosen difficulty (controls complexity parameters) and provides the hidden objective/state.
  - Monitor: enforces response/query formats, produces environment feedback, and detects termination (objective achieved or max turns).
  - Evaluator: scores completed dialogues on multiple dimensions (accuracy, efficiency/turns, invalid-rate/pattern analysis).

## What are the key metrics?

- Accuracy: proportion of tasks successfully completed (final state matches objective).
- Efficiency: relative turn counts on commonly-solved tasks when comparing models.
- Invalid rate / format compliance (via monitor’s validation).
- Turn-based performance curves (accuracy vs allowed interaction turns).

## What are the main results?

- Performance drops from easy → medium → hard across models, suggesting calibrated difficulty.
- Reasoning-focused models outperform non-reasoning baselines, but still fall short on harder interactive settings.
- Task-dependent behavior: more turns help most for Information Probing; less consistent gains for Dynamic Adaptation / State Operation where interpreting feedback is itself challenging.
- Reported finding: o3-mini strong overall and improves notably with more turns; reasoning “ability” is not perfectly aligned with reasoning “efficiency” (some models solve correctly but with more turns).

## How is this similar to GALILEO?

- If GALILEO’s claims involve interactive/iterative reasoning (multi-step tool use, environment feedback, or dialogue-state tracking), MTR-Bench is a directly relevant evaluation framing: sustained reasoning under feedback and turn limits.
- The generator/monitor separation resembles “environment simulator + rule enforcer” patterns used in agent evaluation.

## How is this different from GALILEO?

- MTR-Bench is an evaluation benchmark (task templates + automated scoring), not a method for improving reasoning.
- Focuses on synthetic/templated interactive tasks across four categories; may not match GALILEO’s target domains (if GALILEO is grounded/tool-based).

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO targets real-world grounded tasks (tools, retrieval, planning under real constraints), it may offer higher external validity than templated interactive puzzles.

## Where GALILEO is weaker / needs to improve

- If GALILEO currently reports mostly single-turn or non-interactive evaluations, it may be missing exactly the failure modes MTR-Bench highlights (format compliance, feedback usage over many turns, difficulty scaling).
