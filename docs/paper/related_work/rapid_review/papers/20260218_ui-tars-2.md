# UI-TARS-2 Technical Report: Advancing GUI Agent with Multi-Turn Reinforcement Learning

- Year: 2025
- Venue: arXiv (technical report)
- Authors: Haoming Wang et al.
- URL: https://arxiv.org/abs/2509.02544
- BibTeX key (if we add it): uiTars2_2025
- Tags: agents, gui, multi-turn, reinforcement-learning, robustness, long-horizon

## One-sentence takeaway

UI-TARS-2 is a GUI-native agent trained with a scalable data flywheel and stabilized multi-turn RL plus a hybrid “GUI + terminal/files” sandbox, yielding strong gains on several GUI-agent benchmarks and some cross-domain generalization.

## What problem does it solve?

- Building autonomous GUI agents is bottlenecked by (i) scalable interactive data, (ii) stable multi-turn RL for long-horizon rollouts, (iii) limitations of GUI-only environments (no filesystem/terminal access), and (iv) environment instability for large-scale training/eval.

## What is the core method / protocol?

- A “systematic training methodology” consisting of:
  - Data flywheel for scalable data generation.
  - A stabilized multi-turn RL framework (details not in abstract).
  - Hybrid GUI environment integrating file systems + terminals (so the agent is not constrained to only on-screen actions).
  - Unified sandbox platform enabling large-scale rollouts.
- Model framing: “native GUI-centered agent model” that unifies perception/reasoning/action/memory end-to-end (relative emphasis: native agent model vs tool-augmented pipeline).

## What are the key metrics?

- Benchmark scores on GUI agent suites:
  - Online-Mind2Web
  - OSWorld
  - WindowsAgentArena
  - AndroidWorld
- Game suite performance:
  - Mean normalized score over a 15-game suite
  - Competitiveness on LMGame-Bench

## What are the main results?

- Improves over UI-TARS-1.5.
- Reported benchmark numbers (from abstract):
  - 88.2 (Online-Mind2Web)
  - 47.5 (OSWorld)
  - 50.6 (WindowsAgentArena)
  - 73.3 (AndroidWorld)
- Claimed to outperform strong baselines including proprietary agents (Claude / OpenAI agents) on the above GUI benchmarks.
- Games: mean normalized 59.8 across 15 games (~60% human-level), competitive with frontier proprietary models on LMGame-Bench.
- Generalization: transfers to long-horizon information-seeking tasks and software engineering benchmarks.

## How is this similar to GALILEO?

- Both care about multi-turn / long-horizon robustness and evaluation across extended interactions.
- Both implicitly require stable training/evaluation protocols that don’t collapse under distribution shift across turns.

## How is this different from GALILEO?

- UI-TARS-2 is primarily about training an end-to-end interactive GUI agent (perception + action in environments), whereas GALILEO’s focus (as used in this related-work queue) is multi-turn conversational/behavioral robustness phenomena and measurement.
- Their evaluation is task/agent success on GUI benchmarks, not (primarily) belief/stance stability, persuasion resistance, or conversational sycophancy-style metrics.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO is about *measurement* of multi-turn behavioral drift/robustness, it may offer clearer causal stress tests and interpretable failure modes than end-to-end agent benchmark scores.

## Where GALILEO is weaker / needs to improve

- If GALILEO wants broader coverage of “real” agent settings, it may need closer connection to interactive, tool-using, environment-based long-horizon tasks like those targeted here.
