# RIFT: Reordered Instruction Following Testbed To Evaluate Instruction Following in Singular Multistep Prompt Structures

- Year: 2026
- Venue: ACL ARR (submitted; arXiv)
- Authors: Andrew Jaffe; Noah Reicin; Jinho D. Choi
- URL: https://arxiv.org/abs/2601.18924
- BibTeX key (if we add it): rift-jaffe-2026
- Tags: multi-turn, instruction-following, robustness, prompt-structure, structural-sensitivity, evaluation

## One-sentence takeaway

RIFT isolates *prompt topology* (linear vs non-sequential “jumping” traversal) and finds large accuracy collapses (up to ~72%) when instruction execution requires non-linear navigation, suggesting current LLM instruction-following is strongly positional/sequential rather than truly procedural.

## What problem does it solve?

- Existing instruction-following benchmarks mix together (a) task difficulty/content and (b) prompt structure/order, making it hard to attribute failures specifically to *structural ordering / traversal requirements*.
- For workflows/agents, instructions are often non-linear (jump to step, conditional branches, revisiting prior state). RIFT tests this structural sensitivity directly.

## What is the core method / protocol?

- Dataset construction:
  - Uses rephrased Jeopardy!-style question–answer pairs as controlled content.
  - Keeps the underlying content constant while changing the *prompt structure*.
- Experimental conditions:
  - **Linear prompts:** sequential progression through instructions.
  - **Jumping prompts:** same content, but requires **non-sequential traversal** (explicitly instructed) — i.e., positional continuity is disrupted.
  - Includes an “unconstrained baseline” to calibrate task difficulty.
- Scale:
  - ~10,000 evaluations across **six open-source LLMs**.
- Analysis:
  - Breaks down failure types; highlights instruction-order violations and semantic drift as prominent.

## What are the key metrics?

- Accuracy on the QA task under each prompt structure (baseline vs linear vs jumping).
- Error analysis proportions by failure mode (e.g., instruction-order violations, semantic drift).

## What are the main results?

- **Jumping prompts can drop accuracy by up to ~72% vs baseline**, indicating strong dependence on positional continuity.
- Error analysis suggests **~50%** of failures are due to **instruction-order violations** and **semantic drift**.
- Conclusion: many models appear to internalize instruction-following as a *sequential pattern* rather than an order-invariant “reasoning / control-flow” capability.

## How is this similar to GALILEO?

- Shares the broader theme of **multi-turn robustness**: performance degradation emerges from interaction structure rather than single-turn competence.
- Emphasizes protocol design: controlled manipulations to attribute causal factors (here, structure/topology).

## How is this different from GALILEO?

- RIFT focuses on **instruction topology / ordering** (linear vs jumping) rather than social dynamics (e.g., pressure, sycophancy) or belief drift per se.
- Task is QA-style instruction following; not primarily about preference pressure or truth/stance stability.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO targets *social* multi-turn failure modes (pressure, drift, persuasion), it can capture interaction patterns that RIFT’s structural-only manipulation does not.
- GALILEO may provide richer “why” diagnostics tied to conversational dynamics rather than structural sensitivity alone.

## Where GALILEO is weaker / needs to improve

- GALILEO may under-isolate **prompt topology** effects: some observed multi-turn failures could be explained by non-linear structure sensitivity (RIFT’s factor) rather than the intended social/robustness factor.

## Action items for GALILEO (experiments / method / writing)

- [ ] Add/ablate a **non-linear control-flow condition** (jumping/branching instructions) to ensure GALILEO’s effects are not confounded by structure sensitivity.
- [ ] Include an “order-invariant” evaluation slice: same content, shuffled traversal steps, explicit pointers (“go to step k”), and measure degradation.
- [ ] In related work, position RIFT as evidence that **procedural instruction execution is not topology-robust**, motivating GALILEO’s protocol choices.
