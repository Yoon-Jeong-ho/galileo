# ConvCodeWorld: Benchmarking Conversational Code Generation in Reproducible Feedback Environments

- Year: 2025
- Venue: ICLR 2025 (arXiv)
- Authors: Hojae Han; Seung-won Hwang; Rajhans Samdani; Yuxiong He
- URL: https://arxiv.org/abs/2502.19852
- BibTeX key (if we add it): Han2025ConvCodeWorld
- Tags: multi-turn, code, feedback, evaluation, benchmark

## One-sentence takeaway

ConvCodeWorld/ConvCodeBench benchmark interactive code generation under controlled combinations of compilation/execution/verbal feedback, revealing large performance swings and generalization gaps across feedback regimes.

## What problem does it solve?

- Existing code-generation benchmarks are mostly single-turn or lack realistic *multi-turn* feedback diversity (compile errors, partial tests, natural language critique), making it hard to evaluate “pair-programming” style agents/LLMs.
- Dynamic verbal feedback (e.g., from humans or strong LLMs) can be expensive and non-reproducible; the paper aims for reproducible, systematic evaluation.

## What is the core method / protocol?

- **ConvCodeWorld**: a reproducible *interactive* benchmark environment that simulates **9 interactive code generation scenarios** and varies **feedback** along three axes:
  - Compilation feedback
  - Execution feedback with varying test coverage
  - Verbal feedback (generated by GPT-4o) at different “expertise” levels
- **Feedback combinations** are systematically composed to test how models use different signals.
- **ConvCodeBench**: a **static** benchmark built from **pre-generated feedback logs** to approximate ConvCodeWorld without requiring on-the-fly verbal feedback generation.

## What are the key metrics?

- Multi-turn success-oriented metrics including:
  - **Recall** (problems solved)
  - **MRR** (problems solved in fewer turns vs. ranking/efficiency trade-off)
- Proxy validation: **Spearman rank correlation** between ConvCodeBench and ConvCodeWorld scores (reported 0.82–0.99).

## What are the main results?

- Model performance varies substantially depending on which feedback signals are available.
- With sufficient feedback, **weaker models** can outperform **single-turn** results of stronger models that receive no feedback.
- Training on a particular feedback regime can **hurt generalization** to unseen feedback combinations.
- **MRR vs Recall trade-off**: models that solve quickly (high MRR) may solve fewer total tasks (lower Recall), and vice versa.
- ConvCodeBench tracks ConvCodeWorld well (Spearman 0.82–0.99), suggesting static logs can be a cheaper evaluation proxy.

## How is this similar to GALILEO?

- Both care about **interactive / multi-step** behavior rather than one-shot outputs.
- Highlights that the **structure and quality of feedback** (tests, compiler errors, natural language critique) strongly shapes outcomes—relevant for designing GALILEO’s training/eval loops.

## How is this different from GALILEO?

- This work is primarily a **benchmark + environment** for conversational code generation, not a new agent architecture.
- Focuses on code tasks and feedback modalities; GALILEO may target broader interactive reasoning/planning beyond code (depending on our scope).

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO provides a unified agent framework, tool-use policy, or learning method, it may be stronger on *method* rather than benchmarking.

## Where GALILEO is weaker / needs to improve

- If GALILEO evaluation doesn’t explicitly vary feedback regimes, we may be missing failure modes / brittleness to feedback distribution shift.
- If we rely on expensive feedback generation, ConvCodeBench-style static logs could be a cost-saving alternative.
