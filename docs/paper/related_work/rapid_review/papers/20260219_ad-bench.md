# AD-Bench: A Real-World, Trajectory-Aware Advertising Analytics Benchmark for LLM Agents

- Year: 2026
- Venue: arXiv
- Authors: Lingxiang Hu, Yiding Sun, Tianle Xia, Wenwei Li, Ming Xu, Liqun Liu, Peng Shu, Huan Yu, Jie Jiang
- URL: https://arxiv.org/abs/2602.14257
- BibTeX key (if we add it): adbench2026
- Tags: agents, benchmark, trajectories, tool-use, multi-turn, marketing-analytics

## One-sentence takeaway

A real-world benchmark for LLM agents in advertising analytics that evaluates both final-answer correctness and how well an agent’s tool-call trajectory matches expert reference trajectories, using replay to keep ground truth up-to-date.

## What problem does it solve?

- Existing agent benchmarks are often “toy” or static QA-style and don’t reflect real production analytics settings with evolving data/policies and multi-tool workflows.
- In ads/marketing analytics specifically: (1) ground truth becomes obsolete as data and rules change, (2) we lack evaluation of the *process* (tool-call trajectories), and (3) task requests are long-tail and easy benchmarks overestimate capability.

## What is the core method / protocol?

- Construct AD-Bench from real user marketing analysis requests in an online ads analytics platform.
- Domain experts solve requests using professional tools; record:
  - a verifiable reference answer
  - the *reference tool-call execution trajectory*
- During evaluation:
  - “replay” and re-execute the reference tool calls to regenerate up-to-date ground-truth answers (mitigates obsolescence).
  - evaluate agents on two axes:
    1) outcome correctness (Pass@k via an LLM judge)
    2) trajectory quality via “trajectory coverage” (whether expert trajectory appears as a sub-trajectory within agent’s trajectory).
- Stratify tasks into L1–L3 using trajectory complexity; curate a subset of 100 “unique-trajectory” tasks (claimed unsolvable via alternative tools/trajectories) for finer-grained trajectory evaluation.

## What are the key metrics?

- Pass@1 / Pass@3 for answer correctness (judge-based)
- Trajectory coverage (sub-trajectory match to expert reference)
- Breakdown error analysis dimensions: trajectory errors, parameter errors, hallucinations, calculation errors, dependency errors, long-context limitations

## What are the main results?

- On the full benchmark, they report strong models reaching roughly Pass@1 ~68% and Pass@3 ~83% (Gemini-3-Pro).
- On the hardest level (L3), performance drops substantially (e.g., Pass@1 ~49% and Pass@3 ~62% for Gemini-3-Pro) with trajectory coverage ~70%.
- Conclusion: even SOTA models have sizable gaps on complex, multi-step, multi-tool ads analytics tasks.

## How is this similar to GALILEO?

- Strong emphasis on *agent evaluation in realistic tool-using environments*.
- Treats execution as a trajectory and argues that final answer alone is insufficient; trajectory/process metrics matter.
- Explicitly addresses benchmark brittleness via “replay” / dynamic ground-truth regeneration.

## How is this different from GALILEO?

- Domain-specific: focused on advertising/marketing analytics tools and business definitions/metrics.
- Their trajectory metric is “coverage” (sub-trajectory inclusion) rather than, e.g., cost/latency/robustness or more semantic plan quality measures.
- Uses LLM-as-a-judge for outcome correctness; depends on access to the platform’s tool environment for replay.

## Where GALILEO is stronger / cleaner (if true)

- Opportunity: propose more general, domain-agnostic trajectory metrics (cost, redundancy, tool-selection optimality, parameter validity) beyond sub-trajectory coverage.
- Opportunity: stronger methodology for “unique trajectory” validation (formalizing alternative-tool impossibility, ablations).

## Where GALILEO is weaker / needs to improve

- If GALILEO currently relies on static QA-style labels, AD-Bench’s replay-based ground-truth refresh is a compelling pattern to cite and potentially adopt.
- If GALILEO lacks process-based evaluation, AD-Bench is a concrete precedent for publishing trajectory-aware metrics.

## Action items for GALILEO (experiments / method / writing)
