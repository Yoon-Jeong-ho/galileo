# Do Chatbot LLMs Talk Too Much? The YapBench Benchmark

- Year: 2026
- Venue: arXiv
- Authors: Vadim Borisov; Michael Gröger; Mina Mikhael; Richard H. Schreiber
- URL: https://arxiv.org/abs/2601.00624
- BibTeX key (if we add it): borisov2026yapbench
- Tags: verbosity, evaluation, length-bias, benchmark

## One-sentence takeaway

YapBench is a small, reference-based benchmark that quantifies *excess* verbosity on “brevity-ideal” prompts using character-length-over-minimal-baseline metrics, exposing large cross-model variance and category-specific over-generation failure modes.

## What problem does it solve?

- Assistant LLMs often produce unnecessarily long answers on prompts where a short response is sufficient (extra hedging, boilerplate, formatting, unsolicited explanation), which increases cognitive load and token cost.
- Preference training and LLM-judge evaluation setups can introduce *length bias* (longer answers get higher preference scores even at similar quality), so we need a way to measure verbosity as a first-class outcome.

## What is the core method / protocol?

- Curate a dataset of “brevity-ideal” single-turn prompts, each paired with a **minimal sufficient baseline answer** and a category label.
- Three prompt categories (v0.1):
  - (A) Minimal / ambiguous / low-information inputs → ideal: short clarification or minimal acknowledgment.
  - (B) Closed-form factual questions → ideal: very short stable answers.
  - (C) One-line coding/command tasks → ideal: exactly a one-liner.
- Metrics:
  - **YapScore**: excess response length beyond baseline, measured in **characters** (tokenizer-independent).
  - **YapIndex**: category-balanced aggregation (uniform average of category-level medians).
  - (Also discussed: cost-oriented “YapTax” and diagnostics around different over-generation types.)
- Evaluate a large set of assistant models and report distributions + failure modes per category.

## What are the key metrics?

- YapScore (chars over baseline) per prompt.
- YapIndex (uniform category-weighted average of category median YapScores).
- Qualitative failure modes by category (e.g., “vacuum-filling” on ambiguous inputs; explanation/formatting overhead on one-line technical prompts).

## What are the main results?

- Across assistant LLMs, verbosity beyond minimal-sufficient baselines varies by **an order of magnitude** in median excess length.
- Over-generation is not uniform: different models “yap” for different reasons, and the dominant failure modes differ across the three categories.
- The paper motivates YapBench as a lightweight, repeatable way to track verbosity behavior over time via a leaderboard.

## How is this similar to GALILEO?

- Both are about *behavior under interaction-style evaluation constraints* rather than only static accuracy: YapBench isolates a specific conversational failure mode (unnecessary verbosity) that can systematically distort perceived helpfulness.
- If GALILEO uses LLM-as-a-judge or preference-style evaluation anywhere, YapBench’s framing of **length bias** is directly relevant: long answers may “look better” to judges or humans even when they are not better.

## How is this different from GALILEO?

- YapBench is **single-turn** and targets brevity-ideal prompts; GALILEO (from the surrounding related-work queue) appears primarily focused on **multi-turn** dynamics (drift, pressure, jailbreaks, sycophancy, belief change).
- YapBench evaluates verbosity/over-generation, not truthfulness/safety/consistency per se—though it can correlate with those.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO studies multi-turn robustness or pressure-induced behavior changes, it covers interaction dynamics YapBench does not address.

## Where GALILEO is weaker / needs to improve

- If GALILEO relies on win-rate style LLM-judge evaluation, it should explicitly control for **response length** (or report length-aware metrics), otherwise improvements may partially be verbosity artifacts.
