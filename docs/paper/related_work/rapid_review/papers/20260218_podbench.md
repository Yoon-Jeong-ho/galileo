# PodBench: A Comprehensive Benchmark for Instruction-Aware Audio-Oriented Podcast Script Generation

- Year: 2026
- Venue: arXiv (cs.CL)
- Authors: Chenning Xu, Mao Zheng, Mingyu Zheng, Mingyang Song
- URL: https://arxiv.org/abs/2601.14903
- BibTeX key (if we add it): xu2026podbench
- Tags: audio, podcast, dialogue, benchmark, instruction-following, long-context, evaluation

## One-sentence takeaway

PodBench is a 800-sample, long-context (up to ~21K tokens) benchmark for context-grounded, instruction-aware podcast *script* generation with a two-stage evaluation separating instruction-following from audio-oriented script quality.

## What problem does it solve?

- Podcast script generation (multi-speaker, listener-oriented, grounded in provided materials) is increasingly important in AI-podcast products, but lacks a comprehensive benchmark and a task-appropriate evaluation scheme.
- Existing writing benchmarks often use generic, uniform criteria that can miss domain-specific preferences (e.g., “audio-first” engagement) and can conflate constraint satisfaction with overall script usefulness.

## What is the core method / protocol?

- **Dataset construction (PodBench):** 800 test instances (400 EN + 400 ZH) designed to mimic realistic AI-podcast usage.
  - Inputs include **instruction + contextual grounding documents** (single- and multi-document; up to 10 docs; prompt length up to ~21,649 tokens).
  - Instructions are synthesized to reflect **8 requirement dimensions** found in real AI-podcast scenarios:
    1) focused content, 2) core intent, 3) script structure, 4) specific expressions, 5) language, 6) speaker profiles/personas, 7) speaker number (1–4), 8) podcast length.
  - Quality filtering: LLM-assisted safety/instruction-document relevance checks + human verification.
- **Evaluation framework (two-stage):**
  - **Stage 1: Instruction Following (0–100).** LLM judge derives a query-specific checklist (explicit + implicit constraints), audits output per item with scores {0, 0.5, 1}, then normalizes.
  - **Stage 2: Podcast Script Quality (0–100).** Audio-first rubric with weighted dimensions:
    - Content Substance (45): depth, unique insights vs shallow summarization.
    - Narrative Engagement (30): hooks, pacing, transitions, retention.
    - Conversational Naturalness (25): speakable phrasing, vividness; penalizes overly complex/jargony text.
  - **Final score:** average(Stage1, Stage2), plus dimension breakdowns.

## What are the key metrics?

- Instruction Following score (0–100) from checklist auditing.
- Podcast Script Quality score (0–100) from rubric:
  - Content Substance (0–45)
  - Narrative Engagement / “Structure” (0–30)
  - Conversational Naturalness / “Language” (0–25)
- Final PodBench score: average of Instruction Following and overall Podcast Script Quality.

## What are the main results?

- **Proprietary models** (e.g., Claude/GPT/Gemini variants) generally achieve the best overall results.
- **Open-source models with explicit reasoning (“thinking mode”)** are reported to be **more robust** on long-context and multi-speaker coordination than standard instruct baselines.
- A persistent gap appears between **constraint satisfaction** and **content substance**:
  - High instruction-following does **not** guarantee high-quality, substantive scripts.
  - Content Substance is typically the hardest dimension even when Narrative Engagement / Conversational Naturalness are decent.
- Analyses highlight:
  - **Longer inputs** more consistently hurt **Instruction Following** than Script Quality (adherence drops as context grows, especially for open models).
  - **More speakers (3–4)** introduce a “coordination tax” that disproportionately impacts instruction-following (role/turn tracking).
  - Metric validation: their combined protocol aligns better with human preference than simpler baselines (reported on a held-out set).

## How is this similar to GALILEO?

- If GALILEO targets grounded long-form generation and/or multi-agent/multi-speaker discourse, PodBench surfaces the same core difficulties:
  - long-context constraint tracking,
  - maintaining coherent multi-speaker structure,
  - avoiding “fluent but shallow” outputs.
- The separation between “did it follow constraints?” and “was it actually good/substantive?” is a useful lens for evaluating GALILEO-like systems.

## How is this different from GALILEO?

- PodBench is **evaluation infrastructure** (dataset + scoring), not a generation method.
- Focuses on **text-level podcast scripts**, not end-to-end audio generation (TTS/prosody/sound design are out of scope).
- Uses **LLM-as-a-judge** heavily; this is scalable but still an approximation of human listening preference.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO has a principled grounding or verification mechanism, it may outperform typical LLMs on PodBench’s biggest failure mode: **content substance without hallucination** over long contexts.

## Where GALILEO is weaker / needs to improve

- Any weaknesses in long-context instruction retention or multi-speaker planning will likely show up as:
  - high surface fluency but low Content Substance,
  - speaker role drift / turn-taking inconsistencies,
  - missing constraint items under long prompts.

## Action items for GALILEO (experiments / method / writing)

- [ ] Consider adopting a **two-stage eval** internally: (a) deterministic/constraint checks + (b) audio-first rubric (substance/engagement/speakability).
- [ ] Add stress tests varying **(i) context length** and **(ii) speaker count** to quantify “coordination tax” and long-context adherence decay.
- [ ] Track and mitigate the “**instruction-following vs substance divergence**”: create metrics or targeted training/eval sets where “deep grounded discussion” is rewarded explicitly.

- Dataset scale and difficulty: “800 samples … inputs up to 21K tokens … complex multi-speaker instructions.”
