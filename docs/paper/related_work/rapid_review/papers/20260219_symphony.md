# SYMPHONY: Synergistic Multi-agent Planning with Heterogeneous Language Model Assembly

- Year: 2025 (arXiv Jan 2026)
- Venue: NeurIPS 2025 (arXiv)
- Authors: Wei Zhu; Zhiwen Tang; Kun Yue
- URL: https://arxiv.org/abs/2601.22623
- BibTeX key (if we add it): symphony2025
- Tags: agents, multi-agent, planning, MCTS, diversity

## One-sentence takeaway

SYMPHONY improves MCTS-style planning for LLM agents by using a *heterogeneous pool of LLM agents* to generate more diverse rollouts/branches than repeated sampling from a single model.

## What problem does it solve?

- MCTS+LLM planning commonly uses one LLM repeatedly with near-identical prompts, which often yields highly similar rollouts (low branch diversity).
- Low diversity reduces exploration, increases redundancy/token cost, and can trap planning in local optima on hard multi-step tasks.

## What is the core method / protocol?

- Maintain a pool of heterogeneous LLM agents (different “reasoning styles” / pretraining sources).
- During MCTS planning, assign different agents to propose candidate actions/continuations at search nodes (and likely to evaluate/score branches).
- The key design intent is “diversity-aware search”: diversity comes from model heterogeneity rather than only from sampling temperature.

## What are the key metrics?

(From abstract/intro; paper likely reports these across benchmarks.)

- Task success / completion rate on planning benchmarks.
- Compute efficiency proxies (e.g., number of rollouts / token budget) to reach solutions.
- Diversity of generated branches/rollouts (qualitative or measured via similarity metrics).
- Comparison against prior MCTS+single-LLM baselines.

## What are the main results?

- Across multiple benchmark tasks, SYMPHONY improves planning performance versus single-agent/single-model MCTS baselines.
- Works with open-source LLMs (deployable on consumer hardware) and improves further with stronger API LLMs.

## How is this similar to GALILEO?

- Shared theme: *multi-turn* / multi-step trajectories where failures can compound across steps.
- Both care about evaluation protocols that reflect realistic sequential interaction (not isolated single-turn correctness).

## How is this different from GALILEO?

- SYMPHONY is primarily about *planning/exploration* for agentic problem solving (MCTS branch diversity), not about measuring user-pressure-driven behavioral shifts (e.g., sycophancy/drift).
- It targets “search diversity” rather than “belief/stance stability under conversational pressure”.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO focuses on controlled multi-turn perturbations and stability metrics, it can provide cleaner causal stories about *why* model behavior changes across turns (pressure vs evidence vs drift), which is orthogonal to MCTS planning improvements.

## Where GALILEO is weaker / needs to improve

- If GALILEO involves any agentic planning or tool-use, SYMPHONY-style heterogeneous branching suggests a straightforward baseline/ablation: replace single-policy branching with multi-policy branching to test whether “diversity in rollouts” reduces downstream multi-turn failures.
