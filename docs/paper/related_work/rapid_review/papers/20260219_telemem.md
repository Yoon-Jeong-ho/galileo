# TeleMem: Building Long-Term and Multimodal Memory for Agentic AI

- Year: 2026
- Venue: arXiv
- Authors: Chunliang Chen, Ming Guan, Xiao Lin, Jiaxu Li, Luxi Lin, Qiyi Wang, Xiangyu Chen, Jixiang Luo, Changzhi Sun, Dell Zhang, Xuelong Li
- URL: https://arxiv.org/abs/2601.06037
- BibTeX key (if we add it): TeleMem2026
- Tags: memory, long-term, agents, graph, retrieval, consolidation, multimodal, ReAct

## One-sentence takeaway

TeleMem proposes a long-term (and multimodal) memory system for LLM agents that (i) writes memories efficiently via batched clustering+LLM consolidation and (ii) reads memories as dependency closures over a threaded DAG, improving long-horizon QA accuracy while reducing tokens/latency.

## What problem does it solve?

- Vanilla long-context prompting degrades recall/attention over very long histories.
- Standard RAG memory stores “flat” independent chunks and has weak support for updating/refining memories over time.
- Practical issues: schema-driven hallucinations in user profiles, high per-turn write cost (retrieval + LLM decision each turn), and limited multimodal (video) long-term reasoning.

## What is the core method / protocol?

- **Narrative-grounded extraction for profiles**: extract only dialogue-supported “narrative units” to maintain coherent user profiles and avoid hallucinated schema fields.
- **Structured memory writing pipeline (offline/batched; and an online variant)**:
  - summarize incoming turns
  - retrieve related prior memories
  - globally cluster (summaries + retrieved candidates)
  - LLM consolidates each cluster and assigns actions {add, update, delete, no-op}
  - store consolidated nodes + embeddings
- **Memory graph index**:
  - represent long-term memory as a **directed acyclic graph (DAG)** with timestamps;
  - edges encode (minimal) dependency relations (transitive reduction / pruning redundant edges);
  - update operators Insert / ReInsert maintain incoming edges for new/updated nodes.
- **Closure-based retrieval (“dependency-aware”)**:
  - retrieve seed nodes by similarity;
  - expand backward through dependency edges to include prerequisites (closure);
  - linearize closure by timestamp for a coherent context.
- **Multimodal extension (video)**:
  - store event/object memories from video streams;
  - a ReAct-style loop chooses tools (video retrieval, video RAG, video QA) for observe–think–act reasoning.

## What are the key metrics?

- ZH-4O (Chinese ultra-long role-play benchmark): multiple-choice probing **QA accuracy**.
- LoCoMo (English long-term conversational memory): **LLM-as-a-judge accuracy** across categories (single-hop, multi-hop, open-domain, temporal).
- Efficiency: token usage and runtime (reported vs Mem0 baseline).

## What are the main results?

- **ZH-4O**: TeleMem 86.33% QA accuracy vs Mem0 70.20% (paper claims +19% relative improvement), and also better than long-context baseline (84.92%) in this setup.
- **Efficiency** (on ZH-4O vs Mem0): **43% fewer tokens** and **2.1× speedup** (per abstract).
- **LoCoMo**: overall 61.49% (TeleMem) vs 52.01% (Mem0) and 70.71% (long-context); strong on temporal (78.47%) but weak on multi-hop (20.56%).

## How is this similar to GALILEO?

- Motivated by the same core pain point: long-horizon interactions need **persistent external memory** beyond the model context window.
- Emphasizes **memory lifecycle management** (write/update/delete, consolidation) rather than “just retrieve top-k”.
- Uses explicit structure to reduce inconsistency / hallucination (their DAG dependencies; GALILEO may similarly want structured provenance/relationships).

## How is this different from GALILEO?

- TeleMem’s primary structure is a **dependency DAG** with closure retrieval; if GALILEO focuses on different structure (e.g., explicit provenance, entity-centric state, planning traces), the graph semantics may differ.
- TeleMem leans heavily on **batched clustering + LLM consolidation** as the key write-efficiency lever; GALILEO may instead prioritize online, incremental, controllable updates.
- TeleMem includes a **video multimodal** module and ReAct loop; GALILEO may be text-first.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO has stricter grounding / attribution, it may offer clearer “why retrieved” explanations than closure over learned dependency edges.
- If GALILEO supports richer symbolic constraints (schemas, invariants, conflict resolution), it may handle contradictions more transparently than LLM-based consolidation.

## Where GALILEO is weaker / needs to improve

- If GALILEO still relies on flat RAG or per-turn writes, TeleMem’s **amortized batched writing** is a concrete optimization target.
- If GALILEO lacks dependency-aware retrieval, closure retrieval suggests a route to reduce “missing prerequisites” errors.

## Action items for GALILEO (experiments / method / writing)

- [ ] Consider adding a **dependency/precedence structure** over memory items and test closure-style retrieval vs top-k stitching.
- [ ] Add an **amortized writing mode** (micro-batching + clustering + consolidation) and measure token + latency vs per-turn updates.
- [ ] Add evaluation slices that separate **temporal** vs **multi-hop** reasoning; TeleMem’s weakness on multi-hop is a useful caution.
