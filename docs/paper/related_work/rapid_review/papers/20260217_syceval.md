# SycEval: Evaluating LLM Sycophancy

- Year: 2025
- Venue: AIES 2025 (arXiv)
- Authors: Aaron Fanous, Jacob Goldberg, Ank Agarwal, Joanna Lin, Anson Zhou, Sonnet Xu, Vasiliki Bikia, Roxana Daneshjou, Sanmi Koyejo
- URL: https://arxiv.org/abs/2502.08177
- BibTeX key (if we add it): Fanous2025SycEval
- Tags: sycophancy, persuasion, rebuttals, persistence, multi-turn

## One-sentence takeaway

SycEval measures how often strong user rebuttals make frontier LLMs switch answer correctness (progressive vs regressive sycophancy), showing high overall flip rates and substantial persistence across escalating rhetorical pressure.

## What problem does it solve?

- Quantifies *conversational* sycophancy beyond single-turn “agree with the user” probes, including both:
  - **Progressive sycophancy** (user pushes toward the correct answer; model flips to correct), and
  - **Regressive sycophancy** (user pushes toward an incorrect answer; model flips to incorrect).
- Tests the effect of *how* a user disagrees (in-context vs preemptive; simple vs ethos/justification/citation-based persuasion).

## What is the core method / protocol?

- Tasks/datasets:
  - 500 Q/A from **AMPS Math** (computational)
  - 500 Q/A from **MedQuad** (medical advice)
- Models: ChatGPT-4o (2024-05-13), Claude-Sonnet, Gemini-1.5-Pro (default settings).
- Step 1 (baseline): ask the question; classify the model response as **correct/incorrect/erroneous** using an LLM-as-a-judge (ChatGPT-4o 2024-08-06, T=0) + a small human audit.
- Step 2 (pressure): apply rebuttal “chains” designed to induce an answer change:
  - **In-context rebuttals**: follow up in the same conversation.
  - **Preemptive rebuttals**: standalone counterclaims framed as anticipating the model’s (implied) response.
  - Rebuttal *strength ladder*: **Simple** → +**Ethos** → +**Justification** → +**Citation+Abstract**.
  - They generate contradictory evidence with Llama3-8B to reduce leakage into tested models.
- Label as sycophancy if *any* rebuttal response changes correctness label vs the initial answer:
  - Initially incorrect → becomes correct = **progressive**
  - Initially correct → becomes incorrect = **regressive**

## What are the key metrics?

- **Overall sycophancy rate**: fraction where correctness flips at least once under rebuttal.
- **Progressive vs regressive** sycophancy rates (directional flip).
- **Preemptive vs in-context** sycophancy rate difference (two-proportion z-test).
- **Persistence** of sycophancy across an escalating chain (reported as high persistence; analyzed via chi-square).

## What are the main results?

- High overall sycophancy across conditions: **58.19%** of cases showed a correctness flip.
- Directional split:
  - **Progressive**: **43.52%**
  - **Regressive**: **14.66%**
- By model (overall): Gemini **62.47%**, Claude **57.44%**, ChatGPT **56.71%**.
- **Preemptive** rebuttals yielded higher sycophancy than **in-context** (61.75% vs 56.52%; Z=5.87, p<0.001).
  - For computational tasks, regressive sycophancy increases notably under preemptive vs in-context (reported: 8.13% vs 3.54%, p<0.001).
- Rebuttal strength effects (headline claims):
  - **Simple** rebuttals maximize progressive sycophancy.
  - **Citation+abstract** rebuttals have the highest regressive rates.
- Sycophantic behavior shows high **persistence** across stronger rebuttals: **78.5%** (95% CI [77.2, 79.8]).

## How is this similar to GALILEO?

- Very aligned with “social pressure causes drift” framing, and explicitly separates **helpful flips** (progressive) vs **harmful flips** (regressive)—close to “recovery vs failure” decomposition.
- Uses multi-turn interaction (a rebuttal chain) rather than only single-turn agreement probes.
- Tests *pressure operator design* (strength and framing), which is relevant to GALILEO’s robustness-under-pressure focus.

## How is this different from GALILEO?

- The protocol is a short rebuttal sequence, not a long-horizon “time-to-failure” setup; doesn’t naturally produce survival curves / turn-of-failure distributions across long dialogues.
- Does not include a clean “drift control” (e.g., neutral re-ask) to separate random instability from evidence-driven revision vs social-pressure-driven drift.
- Relies heavily on LLM-as-a-judge for correctness classification (with limited human audit).

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO includes explicit **controls** (neutral paraphrase, evidence-only updates, etc.), it can more cleanly attribute flips to *pressure* rather than generic conversational variance.
- If GALILEO reports **when** failure happens (ToF / survival) and **recovery trajectories**, it provides richer dynamics than a “flip-anytime” rate.

## Where GALILEO is weaker / needs to improve

- GALILEO should adopt SycEval’s explicit **progressive vs regressive** split (or equivalent), because overall flip rate can be ambiguous.
- Consider explicitly varying **rebuttal rhetoric** (simple vs ethos vs citation) since SycEval suggests rhetoric changes *direction* of flips.
