# Flipping the Dialogue: Training and Evaluating User Language Models

- Slug: flipping-dialogue-userlms
- Year: 2025
- Venue: arXiv
- Authors: Tarek Naous; Philippe Laban; Wei Xu; Jennifer Neville
- Links:
  - paper: https://arxiv.org/abs/2510.06552
  - html: https://arxiv.org/html/2510.06552v1
  - code (if any): https://huggingface.co/microsoft/userlm-8b (model release)
- Bibtex: https://doi.org/10.48550/arXiv.2510.06552

## 1) What problem does it study?
User simulation for **multi-turn assistant evaluation**.

Prior work often prompts an instruction-tuned assistant LM to “roleplay a user”. The paper argues this is systematically flawed: assistant LMs generate overly cooperative, well-formed “user” turns, which **overestimates assistant performance**, and (surprisingly) **better assistants can make worse user simulators**.

They propose training dedicated **User Language Models (UserLMs)** that generate user-like utterances conditioned on a **high-level intent**, while also modeling realistic user behaviors like underspecification, incremental refinement, and ending conversations.

## 2) Experimental setup (what is being measured?)
- Task(s): user utterance generation / user simulation in multi-turn human-assistant conversations; downstream impact on assistant evaluation in coding & math conversations.
- Perturbation/pressure type: realism pressure via user behavior (indirect phrasing, partial effort, paraphrase/underspecification, turn-by-turn refinement, termination behavior) rather than explicit social pressure.
- Multi-turn? Y — trained/evaluated on multi-turn dialogues; user LM produces first turn and follow-ups, and decides when to end the conversation via a special token.
- Metrics:
  - Intrinsic distributional alignment: **perplexity** on held-out user utterances (in-domain WildChat test; out-of-domain PRISM).
  - Multi-turn interaction property tests (paper lists six evaluations; details beyond first part not fully extracted in this run): first-turn diversity, decomposing intent across turns, dialogue termination behavior.
  - Robustness as a simulator: adherence to user role + intent vs drift into assistant-like behavior.
  - Downstream assistant performance: success rate of a strong assistant (GPT-4o) when paired with different user simulators.

Data/training highlights (as reported):
- Training data: WildChat (deduplicated to 384,336 conversations; train/val/test split by user).
- Intent conditioning: intents are generated by GPT-4o as high-level summaries of conversation goals.
- Models: full-parameter finetuning of Llama3-8B-Base and Llama3.2-1B-Base → UserLM-8b / UserLM-1b.
- Ablations: train with vs without intent; start from base vs instruction-tuned checkpoint.

## 3) Key findings (bullet)
- **Assistant LMs are poor user simulators**, and **stronger assistants can yield worse simulators** (more “perfect”, cooperative user turns).
- UserLM-8b achieves much better **distributional alignment** to real user utterances (lowest PPL, including on out-of-domain PRISM), and intent conditioning helps across models.
- Starting from a **base** checkpoint is better than starting from an instruction-tuned checkpoint for learning the user role (instruction-tuned models are semantically biased toward assistant behavior).
- Using UserLMs makes evaluation harsher/more realistic: when simulating coding+math conversations, a strong assistant (GPT-4o) drops from **74.6%** (assistant-roleplay user simulator) to **57.4%** (UserLM simulator).

## 4) Limitations / threats
- Intents are generated by GPT-4o; intent generation quality/consistency may shape the learned user behavior and steerability.
- Focus is user-simulation realism rather than explicit **social pressure / persuasion**; may not cover the particular pressure operators GALILEO studies.
- Many evaluations are intrinsic/proxy (PPL, behavioral property tests); mapping to real deployment outcomes depends on how well WildChat/PRISM match the target user population.

## 5) How it relates to GALILEO
- What we can cite it for:
  - **Evaluation artifact warning**: prompting assistants to roleplay users can systematically **overestimate** robustness in multi-turn settings.
  - Motivation to use more realistic, less-cooperative multi-turn user behavior when measuring failure dynamics.
- Where we differ (our delta):
  - GALILEO targets **multi-turn robustness under social pressure** (sycophancy/persuasion) with explicit controls (drift vs revision) and recovery; this paper targets user simulation realism broadly.
- Direct mapping:
  - Survival ↔ indirect: could enable more realistic conversation trajectories that create time-to-failure events, but no explicit survival analysis.
  - TOF ↔ indirect: user simulator affects when/if the assistant fails; not defined as a metric here.
  - Recovery ↔ not a focus (termination is modeled; recovery-after-flip not emphasized).
  - Neutral Re-asking Control ↔ related in spirit (simulator choice as a “control” for evaluation realism), but not an explicit paired neutral/pressure protocol.
