# Benchmarking the Robustness of Agentic Systems to Adversarially-Induced Harms

- Year: 2025
- Venue: arXiv
- Authors: Jonathan Nöther; Adish Singla; Goran Radanović
- URL: https://arxiv.org/abs/2508.16481
- BibTeX key (if we add it): noether2025badacts (guess)
- Tags: agent-safety, robustness, adversarial, benchmark, multi-agent

## One-sentence takeaway

BAD-ACTS is a benchmark + taxonomy for *harmful tool/actions* in multi-agent systems under a “one agent is malicious” threat model, showing high attack success rates and that prompt-only defenses are weak while message-monitoring (guardian) helps.

## What problem does it solve?

- We lack systematic, *action-centric* security evaluations for agentic/multi-agent LLM systems (beyond single-chatbot jailbreaks), especially when an attacker can compromise/instantiate a malicious peer agent.
- Prior safety work often measures toxic text / refusal; agentic systems can take actions via tools (files, money, messaging, bookings), which creates new harm surfaces.

## What is the core method / protocol?

- Proposes a **taxonomy of agentic harms** (high-level + fine-grained categories) and uses it to build **BAD-ACTS** (Benchmark of ADversarial ACTionS).
- BAD-ACTS includes **5 environments** (simulated/emulated tools):
  - Travel Planning (decentralized comms)
  - Personal Assistant (centralized planning + specialists)
  - Financial Article Writing (hierarchical)
  - Code Generation (centralized via “CEO”)
  - Multi-Agent Debate (sequential)
- Dataset:
  - BAD-ACTS-CORE: **188** manually curated “harmful target actions” (often tool-call level targets)
  - BAD-ACTS-EXTENDED: **699** additional actions (curated, less edited) meant for training adversaries/defenses
- **Threat model / attack:** attacker fully controls **one agent**; adversary tries to manipulate other agents into executing a specified harmful target action.
- **Metric:** attack success rate (ASR) via **keyword-based checks** on tool executions / messages (they report higher agreement with humans than an LLM-judge).
- **Baselines / defenses:**
  - “Adversary-aware prompting” = prepend/append generic security instructions to system prompts (constrained not to override role)
  - “Guardian agents” = **message monitoring** agent(s) intercept messages and can terminate episode on suspected adversarial behavior (zero-shot monitoring framing)

## What are the key metrics?

- **ASR (attack success rate)** across environments, harm categories, and models.
- Defense evaluation: **relative change in ASR**, plus reported **false positive rate** for guardian monitoring in benign episodes.

## What are the main results?

- Across tested models (open + proprietary), **a single malicious agent often succeeds** at inducing harmful actions.
- **Larger models can be more vulnerable** than smaller ones within a family (e.g., Llama 70B vs 8B), consistent with observations in some prior robustness/safety work.
- **Communication structure matters:** centralized/hierarchical structures tend to be safer than decentralized ones.
- **Prompt-only defenses** (generic “be safe” instructions) often help little and can sometimes worsen ASR.
- **Message monitoring / guardian** provides the most consistent ASR reductions, with a reported benign-episode false-positive rate around ~5%.

## How is this similar to GALILEO?

- Shared theme: **multi-turn robustness** of LLM(-agent) behavior under adversarial pressure (here: malicious peer agent rather than user-provided misinformation).
- Highlights that **protocol/structure** (who can talk to whom; who can execute tools) is a first-class safety/robustness variable — analogous to GALILEO’s emphasis on evaluation protocol shaping measured robustness.

## How is this different from GALILEO?

- BAD-ACTS is primarily **agent-security / harmful-action execution** (tool-call harm taxonomy) rather than belief-drift / factual stability under evidence vs pressure.
- Their outcomes are **action-level** (did the harmful tool action happen?), not “stayed correct over rounds / turn-of-failure” style factual metrics.

## Where GALILEO is stronger / cleaner (if true)

- If we frame GALILEO as measuring *epistemic stability* (survival/TOF) under controlled interventions, we can be **cleaner on causal attribution** (pressure vs evidence) than action-harm benchmarks.
- GALILEO-style time-to-failure metrics could complement BAD-ACTS by quantifying **how quickly** an agent succumbs (not just whether it ever does) in long interactions.

## Where GALILEO is weaker / needs to improve

- We currently don’t benchmark **tool/action harms** under compromised-peer settings; reviewers may ask about “agentic security” adjacency.
- Need a clear statement of threat model differences (malicious peer vs misleading user/environment) to avoid scope confusion.
