# MT-Eval: A Multi-Turn Capabilities Evaluation Benchmark for Large Language Models

- Year: 2024
- Venue: arXiv
- Authors: Wai-Chung Kwan; Xingshan Zeng; Yuxin Jiang; Yufei Wang; Liangyou Li; Lifeng Shang; Xin Jiang; Qun Liu; Kam-Fai Wong
- URL: https://arxiv.org/abs/2401.16745
- BibTeX key (if we add it): mt-eval-kwan-2024
- Tags: multi-turn, evaluation, benchmark, error-propagation, retrieval-distance

## One-sentence takeaway
MT-Eval provides a taxonomy + benchmark of multi-turn interaction patterns and shows many LLMs degrade substantially vs single-turn controls due largely to “distance-to-relevant-content” and error propagation.

## What problem does it solve?
- Existing LLM evaluation is mostly single-turn, while deployed use is often multi-turn; we lack targeted tests that isolate multi-turn conversational capabilities.
- It’s unclear what *drives* multi-turn degradation (vs just “model is weak”).

## What is the core method / protocol?
- Derive a taxonomy of multi-turn interaction patterns from human–LLM chats:
  - **Recollection** (need to recall earlier context)
  - **Expansion** (build on earlier content)
  - **Refinement** (revise/improve earlier answer)
  - **Follow-up** (later question depends on earlier content)
- Build **1170** multi-turn queries per category via:
  - augmenting existing datasets, and
  - creating new examples with GPT-4 to reduce data leakage.
- Create **single-turn counterparts** for the same tasks, to quantify “multi-turn penalty”.
- Evaluate **11 LLMs**; analyze correlates of performance drops.

## What are the key metrics?
- Task accuracy / performance on:
  - multi-turn version vs the matched single-turn version (i.e., multi-turn degradation).
- Analysis factors highlighted in the abstract:
  - **distance to relevant content** (how far back the necessary info is)
  - **susceptibility to error propagation** across turns.

## What are the main results?
- Closed-source models generally outperform open-source, but some open-source models beat GPT-3.5-Turbo on specific tasks.
- Most models show **significant degradation** in multi-turn vs single-turn.
- Multi-turn degradation is **not well-correlated** with “fundamental capabilities” (i.e., strong single-turn ≠ strong multi-turn).
- Two key drivers: distance-to-relevant-content and error propagation.

## How is this similar to GALILEO?
- Shared framing: multi-turn settings expose failure modes that don’t appear in single-turn evaluation.
- Emphasis on designing evaluations that isolate *interaction dynamics* (history dependence, compounding errors) rather than only final-answer quality.

## How is this different from GALILEO?
- MT-Eval is a **general multi-turn capability** benchmark (taxonomy across recollection/expansion/refinement/follow-up), not specialized to a single robustness phenomenon.
- Focus is on multi-turn *ability drop* vs a single-turn control, rather than adversarial/social-pressure/robustness-specific protocols (if GALILEO is targeted there).

## Where GALILEO is stronger / cleaner (if true)
- If GALILEO targets a specific robustness mechanism (e.g., pressure/drift/jailbreak trajectories), it can offer clearer causal stress-tests than a broad capability benchmark.
- GALILEO-style trajectory metrics may better capture “how failures emerge over time” than a per-example aggregate.

## Where GALILEO is weaker / needs to improve
- Consider adopting MT-Eval’s **matched single-turn controls** more systematically to separate “base competence” from “multi-turn interaction penalty”.
- Consider adopting MT-Eval’s **interaction taxonomy** as an organizing structure for related work and experiment suites.
