# MTRAG: A Multi-Turn Conversational Benchmark for Evaluating Retrieval-Augmented Generation Systems

- Year: 2025
- Venue: TACL 2025 (presented at ACL 2025)
- Authors: Yannis Katsis, Sara Rosenthal, Kshitij Fadnis, Chulaka Gunasekara, Young-Suk Lee, Lucian Popa, Vraj Shah, Huaiyu Zhu, Danish Contractor, Marina Danilevsky
- URL: https://direct.mit.edu/tacl/article/doi/10.1162/TACL.a.19/132114/mtRAG-A-Multi-Turn-Conversational-Benchmark-for
- BibTeX key (if we add it): katsis2025mtrag
- Tags: multi-turn, RAG, benchmark, robustness, evaluation

## One-sentence takeaway

MTRAG is a human-authored multi-turn RAG benchmark (110 conversations; 842 turn-level tasks) designed to surface real-world failure modes like later-turn degradation, non-standalone follow-ups, and unanswerable questions that single-turn RAG benchmarks miss.

## What problem does it solve?

- Standard RAG evaluations are often single-turn; they miss conversational phenomena where later turns depend on prior context, require resolving anaphora/ellipsis, or shift constraints.
- Multi-turn RAG adds extra brittleness: retrieval must remain on-track under context drift; generation must stay faithful while integrating conversation history.

## What is the core method / protocol?

- Dataset/benchmark construction:
  - 110 human-generated conversations averaging 7.7 turns each (total 842 turn-level “tasks”).
  - Four domains/corpora: Wikipedia (ClapNQ), Finance (FiQA), plus newly assembled Govt + Cloud technical documentation.
  - Conversations include varied question types and “answerability” conditions (answerable, unanswerable, partial, conversational).
- Evaluation view:
  - Each turn k becomes an evaluation task that includes the full preceding dialogue (turns 1..k-1) + the current user question.
  - They evaluate generation under three retrieval regimes (as described in the dataset release):
    - Reference: generate using gold/reference passages.
    - Reference+RAG: run retrieval but ensure reference passages appear in top-5.
    - Full RAG: retrieve top-5 passages, then generate.
- They also explore automation via synthetic data generation and LLM-as-a-judge evaluation (high-level claim from the abstract/release).

(ArXiv version linked from the dataset repo: https://arxiv.org/abs/2501.03468 ; dataset repo: https://github.com/ibm/mt-rag-benchmark)

## What are the key metrics?

- The paper emphasizes end-to-end multi-turn RAG quality; the dataset repo foregrounds evaluation dimensions like (names as described in their benchmark framing):
  - Faithfulness / groundedness (to retrieved passages)
  - Appropriateness / naturalness / completeness
- Retrieval quality is provided in BEIR-style task format (Answerable + Partial subsets) for standard IR metrics.

## What are the main results?

- High-level finding (from the abstract): even state-of-the-art LLM RAG systems “struggle” on MTRAG.
- The benchmark is designed to make performance drop visible on:
  - later turns,
  - unanswerable questions,
  - non-standalone follow-ups,
  - cross-domain variation.

## How is this similar to GALILEO?

- Shared motivation: single-shot evaluation overestimates robustness; interactive/multi-turn settings reveal progressive degradation and “hidden” failure modes.
- Both encourage turn-level analysis (per-turn tasks; later-turn difficulty) rather than only aggregate accuracy.

## How is this different from GALILEO?

- Task focus: MTRAG targets *RAG* (retrieval + generation + grounding) in multi-turn conversation; GALILEO is about multi-round correctness/consistency dynamics (e.g., flips / turn-of-failure) under repeated interaction.
- MTRAG’s notion of failure is tightly coupled to retrieval and grounding; GALILEO’s is model-behavioral robustness under repeated pressure/interaction even without retrieval.

## Where GALILEO is stronger / cleaner (if true)

- GALILEO’s survival/turn-of-failure style analysis could offer a clearer, model-agnostic trajectory metric for “how quickly things go wrong” across turns (especially if adapted to multi-turn RAG settings).
- GALILEO can provide a taxonomy over *answer flips* / degradation patterns that complements RAG-specific groundedness metrics.

## Where GALILEO is weaker / needs to improve

- If reviewers expect coverage of RAG-style multi-turn tasks, GALILEO should explicitly position itself relative to multi-turn RAG benchmarks like MTRAG (scope difference + why our setting matters).
- GALILEO may need clearer guidance on what “correctness across turns” means when the knowledge source changes (retrieval updates) if we ever claim generality to RAG agents.
