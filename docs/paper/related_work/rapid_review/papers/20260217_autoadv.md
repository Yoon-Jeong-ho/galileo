# AutoAdv: Automated Adversarial Prompting for Multi-Turn Jailbreaking of Large Language Models

- Year: 2025
- Venue: NeurIPS 2025 Lock-LLM Workshop (arXiv)
- Authors: Aashray Reddy; Nicholas Saban; Andrew Zagula
- URL: https://arxiv.org/abs/2511.02376
- BibTeX key (if we add it): autoadv2025
- Tags: multi-turn, jailbreak, attacks, automated, adversarial-prompting, red-teaming

## One-sentence takeaway

AutoAdv is a training-free black-box framework that iteratively rewrites harmful requests over multiple turns (using pattern/temperature managers) and reports very high multi-turn jailbreak success, highlighting the gap between single-turn alignment and multi-turn robustness.

## What problem does it solve?

- Most jailbreak evaluation is single-turn, but realistic misuse is multi-turn and adaptive; we need scalable automated multi-turn red-teaming to measure vulnerability.

## What is the core method / protocol?

- Frames jailbreaking as iterative, feedback-driven rewriting across turns.
- Uses three adaptive components:
  - **Pattern manager**: logs successful rewriting “patterns” and reuses them to steer future rewrites.
  - **Temperature manager**: dynamically changes rewriting sampling temperature based on observed failure modes (exploration strategies).
  - **Two-phase rewriting**: (1) disguise harmful request to evade safety filters, then (2) iteratively refine based on target responses.
- Black-box: uses only the target model’s text responses (no weights/gradients).
- Evaluation setup (as described): ~700 harmful prompts drawn from AdvBench (500) + HarmBench (200); run up to ~6 turns.

## What are the key metrics?

- Attack Success Rate (ASR), reported as a function of number of turns (multi-turn vs single-turn baselines).

## What are the main results?

- Reports ASR **up to ~95% on Llama-3.1-8B within 6 turns**, and **multi-turn improves ASR by as much as ~24%** versus single-turn baselines.
- Evaluated across multiple targets (named in abstract/introduction): Llama-3.1-8B, GPT-4o mini, Qwen3-235B, Mistral-7B.

## How is this similar to GALILEO?

- Shares the key theme that **multi-turn interaction dynamics** expose failures that are missed in single-turn evaluation.
- Emphasizes **trajectory-based evaluation** (performance changes across turns), which is conceptually adjacent to time-to-failure / persistence notions.

## How is this different from GALILEO?

- AutoAdv is an **attack generation** framework focused on eliciting harmful content (safety jailbreak), not measuring truthfulness / sycophancy / belief drift under pressure.
- Primary metric is **ASR**, not survival/time-to-inconsistency, recovery-to-truth, or controlled drift vs evidence-driven revision.

## Where GALILEO is stronger / cleaner (if true)

- If positioned as robustness measurement, GALILEO can contribute **more diagnostic metrics** than a single scalar ASR (e.g., turn-of-failure, survival curves, recovery).
- GALILEO can include **control conditions** to separate “being convinced by evidence” vs “drifting / being manipulated”.

## Where GALILEO is weaker / needs to improve

- Jailbreak work like AutoAdv suggests we should be explicit about **adaptive multi-turn adversaries**; simple fixed multi-turn scripts may underestimate worst-case vulnerability.
