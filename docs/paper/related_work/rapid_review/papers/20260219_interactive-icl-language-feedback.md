# Improving Interactive In-Context Learning from Natural Language Feedback

- Year: 2026
- Venue: arXiv
- Authors: Jonathan Cook; Diego Antognini; Hao Sun; Jingling Li; Natasha Jaques; Claudiu Musat; Edward Grefenstette (Google DeepMind)
- URL: https://arxiv.org/abs/2602.16066
- BibTeX key (if we add it): cook2026improving
- Tags: interactive learning, in-context learning, natural language feedback, RL, student-teacher, self-correction, multi-turn

## One-sentence takeaway

Train LLMs with RL on multi-turn “didactic” dialogues (teacher gives natural-language critiques using privileged info) to substantially improve a model’s ability to incorporate corrective feedback across turns and generalize this interactive skill OOD.

## What problem does it solve?

- Baseline/foundation LLMs often fail at *interactive correction*: when a user gives natural-language feedback (“be concise”, “that step is wrong, re-check assumption X”), the model frequently acknowledges but doesn’t actually revise its previous reasoning/output.
- Standard next-token pretraining + single-turn RL/finetuning optimizes static completion quality but does not directly train the conversational *plasticity* needed to update answers given critiques.

## What is the core method / protocol?

- Define **learning from language feedback** as a multi-turn interaction between:
  - a **student** model attempting a verifiable task;
  - a **teacher** model that provides *targeted critique / guidance* in natural language.
- Key trick: **information asymmetry** (teacher is conditioned on privileged info like a reference solution / verifier output), so the teacher does *not* need to be a stronger model.
- Convert single-turn verifiable tasks into **multi-turn didactic interactions**:
  1) student answers;
  2) if verifier says wrong → teacher critiques without revealing final answer;
  3) student tries again; repeat until correct or max turns.
- Train student with RL on sparse outcome reward (correctness), over multiple turns; paper refers to this framing as **RL2F** (RL with language feedback), linking to RL2-style “learn to learn” but via in-context updates rather than inner-loop gradients.
- Also explore “internalizing the teacher”: train on full dialogues including teacher turns, so a single model can predict critiques and self-correct without an external teacher at inference.

## What are the key metrics?

- Multi-turn task success / accuracy on **verifiable** domains (math, coding, puzzles, etc.).
- Comparison across:
  - base model vs single-turn RL vs multi-turn didactic RL.
  - interactive setting (with teacher feedback) vs “self-improvement” setting (model plays both roles).
- OOD transfer: train on one domain (math) and test on other domains.

## What are the main results?

- Frontier models show substantial headroom: they often struggle to integrate corrective feedback on hard reasoning tasks.
- Multi-turn didactic RL dramatically improves interactive performance; a smaller model can approach a much larger model’s performance in multi-turn settings (example given: Gemini 2.5 Flash near Gemini 2.5 Pro on a hard math benchmark after training).
- Improvements transfer OOD: training on math interactions improves performance on diverse domains (coding, puzzles/mazes, logic tasks).
- Qualitative mechanism claim: trained models show higher **in-context plasticity** (actually revise based on critique) vs baselines that tend to repeat initial answers.

## How is this similar to GALILEO?

- Both target **agent behavior across turns** rather than single-shot correctness.
- Emphasis on *training/evaluating interactive robustness*: whether the system meaningfully updates behavior under feedback signals.
- Uses verifiable tasks and automated checks to scale training signals (analogous to scalable evaluation/feedback loops).

## How is this different from GALILEO?

- This paper is primarily about **training for interactive in-context learning from natural-language critique** (teacher/student dialogues) rather than GALILEO’s likely focus on broader agentic reliability constraints (e.g., calibration, monitoring, or structured oversight—depending on GALILEO’s scope).
- Teacher signal is generated by a model conditioned on privileged info; not necessarily a human-in-the-loop setting.
- Reward is mostly end-task correctness; less about fine-grained safety/constraint satisfaction unless encoded in verifier.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO provides a clearer *evaluation taxonomy* and explicit failure modes for interactive systems, it could position this work as one training recipe within a broader reliability framework.
- If GALILEO uses real user feedback or more realistic interaction distributions, it may better match deployment.

## Where GALILEO is weaker / needs to improve

- Consider adding (or citing) explicit training paradigms for **interactive correction / critique integration**; this paper is a concrete, scalable recipe.
- Ensure GALILEO’s benchmarks include “acknowledge-but-don’t-update” failure cases (the paper’s Figure 3-style phenomenon).
