# CAR-bench: Evaluating the Consistency and Limit-Awareness of LLM Agents under Real-World Uncertainty

- Year: 2026
- Venue: arXiv
- Authors: Johannes Kirmayr; Lukas Stappen; Elisabeth André
- URL: https://arxiv.org/abs/2601.22027
- BibTeX key (if we add it): carbench2026kirmayr
- Tags: multi-turn, tool-use, consistency, uncertainty, limit-awareness, agents, policies

## One-sentence takeaway

CAR-bench evaluates multi-turn tool-using LLM agents in an in-car assistant environment, emphasizing *consistency across retries* and *limit-awareness* (don’t hallucinate missing tools/info; disambiguate before acting).

## What problem does it solve?

- Existing agent benchmarks over-emphasize single-run task completion in “ideal” settings (fully specified requests, complete tool coverage) and under-measure real deployment failure modes.
- Real users provide incomplete/ambiguous requests; agents must decide when to ask clarifying questions, gather info, or admit limitations.
- Agents often “complete” by fabricating (hallucination) or taking premature actions under uncertainty; policies add additional constraints that can be violated stochastically.

## What is the core method / protocol?

- A benchmark/environment for an automotive (in-car assistant) domain with:
  - an LLM-simulated user generating multi-turn interactions following task instructions,
  - an LLM agent constrained by domain policies,
  - 58 interconnected tools spanning navigation, productivity, charging, and vehicle control,
  - an interactive environment with mutable state + fixed context variables + static databases.
- Task types (as described in abstract/intro):
  - **Base**: standard tool-using task completion.
  - **Hallucination**: requests where needed tools/information are missing → tests *capability/limit awareness* (acknowledge inability vs fabricate).
  - **Disambiguation**: underspecified requests → tests resolving uncertainty via clarification or internal info gathering *before* acting.
- Reports both occasional success and repeatable success via multi-trial evaluation.

## What are the key metrics?

- **Pass@k**: succeeds in *at least one* out of k trials (paper uses k=3).
- **Pass^k** (written as Passˆk / “consistent pass”): succeeds in *all* k trials (paper highlights k=3 as deployment-readiness proxy).
- Breakdowns by task type (Base vs Hallucination vs Disambiguation) and error analysis (policy violations, premature actions, fabricated responses).

## What are the main results?

- Large gap between occasional and consistent success across task types.
- Disambiguation is especially hard: the paper reports a drop for a frontier “reasoning” model from **68% Pass@3** to **36% Pass^3** on Disambiguation tasks (numbers in intro).
- Hallucination tasks expose a tendency to fabricate rather than acknowledge missing capability; “thinking” models improve but reportedly plateau around **~60% Pass^3** (intro).
- Overall message: even strong models are not reliably consistent under multi-turn uncertainty + policy constraints.

## What are the limitations?

- Domain specificity: in-car assistant setting (tools/policies) may not directly transfer to other social-pressure settings.
- Uses an LLM-simulated user; behavior depends on simulator assumptions.
- Intro-level numbers only here (rapid review); further details (dataset size, model list, statistical treatment) would need full paper pass.

## How is this similar to GALILEO?

- Emphasizes *multi-turn reliability* rather than single-turn accuracy.
- Explicitly evaluates failure under uncertainty/pressure to “satisfy the user” (completion–compliance tension), which is adjacent to social pressure/sycophancy dynamics.
- Uses time/trajectory style thinking (retries; consistency across runs) akin to robustness-to-failure framing.

## How is this different from GALILEO?

- Focuses on tool-using in-car assistant tasks with policy constraints, not primarily on belief revision / social persuasion / sycophantic agreement.
- Measures consistency across repeated trials (Pass^k) rather than within-trajectory “flip / recovery / time-to-failure” style metrics (though conceptually related).

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO uses controlled conversational pressure protocols (e.g., explicit persuasion/sycophancy stimuli) and tracks within-episode belief trajectories, it may provide a more targeted lens on *belief drift and recovery* than CAR-bench’s task-success framing.

## Where GALILEO is weaker / needs to improve

- CAR-bench’s **Pass^k** style metric is a clean “deployment readiness” measure; GALILEO should consider an analogous *consistency across reruns / seeds / paraphrases* metric in addition to within-dialogue dynamics.

## Action items for GALILEO (experiments / method / writing)

- [ ] Add a “consistent success” metric analogous to **Pass^k** (e.g., succeed in all N reruns under paraphrased/seeded variants).
- [ ] Add explicit *limit-awareness* cases: prompts where the correct behavior is to refuse/specify uncertainty rather than comply.
- [ ] In error taxonomy, include a “completion–compliance tension” category (premature action / fabricated support) and quantify it.

## Quotes / details to potentially cite

- CAR-bench introduces **Hallucination** tasks (missing tools/info → test limit-awareness) and **Disambiguation** tasks (underspecified requests → clarification/info gathering before action).
- Uses **Pass^3** (success in all 3 trials) vs **Pass@3** (at least one success) to expose consistency gaps; intro reports Disambiguation dropping (example: 68% → 36% for a frontier reasoning model).
