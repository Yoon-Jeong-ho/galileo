# Evaluating Long-Term Memory for Long-Context Question Answering (LoCoMo)

- Year: 2025
- Venue: Metacognition in Generative AI @ NeurIPS workshop (poster)
- Authors: Alessandra Terranova, Björn Ross, Alexandra Birch
- URL: https://arxiv.org/abs/2510.23730
- BibTeX key (if we add it): Terranova2025LoCoMoMemory (placeholder)
- Tags: long-horizon, memory, long-context, multi-turn, evaluation, efficiency, limit-awareness

## One-sentence takeaway

A systematic comparison of semantic/episodic/procedural memory augmentation on LoCoMo shows you can cut context tokens by >90% while keeping competitive QA accuracy, with the “best” memory type depending strongly on base model capability.

## What problem does it solve?

- Evaluates which long-term memory strategies are effective for *very long, multi-session* conversational QA, where simply stuffing the full dialogue into the prompt is costly and can degrade reliability.
- Clarifies trade-offs between memory-system complexity, accuracy, efficiency (token cost), and metacognitive behaviors (recognizing “I don’t know”).

## What is the core method / protocol?

- Task: long-context conversational QA on LoCoMo (synthetic, very long dialogues) plus validation on QMSum (human meeting dataset).
- Compares multiple “memory for QA” strategies under a unified evaluation prompt:
  - Full-context prompting (baseline).
  - **Semantic memory** via RAG (retrieve relevant chunks instead of full context).
  - **Agentic semantic memory** (more autonomous retrieval / structured memories; details in paper).
  - **Episodic memory** via in-context learning with *reflections* from past interactions (experience → textual feedback stored → reused).
  - **Procedural memory** via prompt optimization (task procedure encoded in the prompt).
- Uses a consistent prompt across question types (unlike prior work that changed prompts by reasoning type), to better isolate memory mechanism effects.

## What are the key metrics?

- Answer accuracy: **F1** (with an instruction to copy exact words from the conversation where possible).
- Efficiency: **average token length per query**.
- Relative performance: **average F1 ranking across categories**.
- Special handling for adversarial “unanswerable from dialogue” questions: score 1 if output contains a “no information available”-style refusal, else 0.

## What are the main results?

- Memory-augmented methods reduce token usage by **>90%** while maintaining *competitive* accuracy vs full-context prompting.
- “Which memory helps” depends on model strength:
  - Foundation (base) models benefit most from **RAG**.
  - Stronger instruction-tuned models benefit more from **episodic learning via reflections** and more complex / agentic semantic memory.
- Episodic memory can improve **limit-awareness** (better behavior on adversarial / unanswerable questions; “knowing what it doesn’t know”).

## How is this similar to GALILEO?

- Both care about *multi-turn* behavior over long horizons and about metrics/protocols that don’t collapse everything into a single-turn score.
- Their emphasis on *trajectory efficiency* (token cost) and on *limit-awareness* is adjacent to GALILEO’s interest in reliability under extended interaction.

## How is this different from GALILEO?

- Focus is **long-context QA and memory architectures**, not robustness under **social pressure / persuasion** or belief drift vs evidence-based revision.
- Main outcome is QA F1 + token cost; no explicit time-to-failure / survival-style robustness metric, and no pressure operators.

## Where GALILEO is stronger / cleaner (if true)

- GALILEO’s domain can cleanly isolate *pressure-driven drift* vs *evidence-driven revision* (with explicit control conditions), which is not the target here.
- GALILEO’s evaluation can naturally incorporate turn-of-failure and recovery-after-flip metrics.

## Where GALILEO is weaker / needs to improve

- If GALILEO uses long dialogues, this paper is a reminder to report (and optimize) **token efficiency** and to consider memory augmentation baselines to avoid confounding “model fails because the prompt is huge.”
