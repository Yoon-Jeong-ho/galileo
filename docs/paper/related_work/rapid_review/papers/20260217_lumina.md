## One-sentence takeaway

LUMINA proposes an *oracle counterfactual* evaluation framework that measures which missing skills (planning, state tracking, history pruning) are actual bottlenecks for multi-turn, long-horizon LLM agents on controlled procedural environments.

## What problem does it solve?

- Real-world multi-turn agent benchmarks make it hard to attribute failures to specific underlying skills (planning vs state tracking vs long-context handling), because there can be many valid trajectories and “oracle” labels are expensive.
- The paper aims to *isolate* and *quantify the criticality* of individual skills by injecting perfect information (“oracle interventions”) and measuring performance gains.

## What is the core method / protocol?

- **Oracle counterfactual framework:** ask “how would this agent perform if it had perfect access to skill X?” and measure delta in task success.
- Three oracle interventions (and combinations):
  - **Planning oracle:** provides an optimal single-turn subtask / next-step guidance along an optimal trajectory.
  - **State-tracking oracle:** provides accurate current environment state.
  - **History pruning oracle:** rewrites/summarizes context to remove distractors and keep compact relevant history.
- **Procedurally generated, game-like environments** with tunable complexity and computable optimal actions at each step:
  - **ListWorld:** mutate a Python list using only `pop` actions (long-horizon careful edits).
  - **TreeWorld:** locate a target node via repeated `get_children` actions.
  - **GridWorld:** navigate a 2D grid to reach a target while avoiding holes.

## What are the key metrics?

- **Success rate** over full episodes / trajectories (long-horizon completion).
- **Per-step accuracy**: whether the chosen action is among the set of optimal actions at that step.
- (Qualitative) gap analysis between high per-step accuracy and low long-horizon success as evidence of **compounding errors**.

## What are the main results?

- There can be **large discrepancies** between high per-step accuracy and **low end-to-end success** on long trajectories, highlighting that compounding errors dominate.
- Oracle interventions generally help, but **which oracle matters depends on model size and environment properties** (i.e., no universally dominant fix beyond “planning often helps”).
- Different environments show different patterns of gains from oracles, suggesting **environment-specific bottlenecks**.

## How is this similar to GALILEO?

- Shares the theme that **multi-turn settings expose failure modes not visible in single-turn evaluation**, especially via *compounding* effects.
- Provides a concrete protocol idea: **counterfactual interventions** to attribute failure to specific missing capabilities.

## How is this different from GALILEO?

- Focuses on **agentic, goal-oriented environments** (planning/state tracking) rather than conversational belief/stance dynamics or social/persuasion settings.
- Uses **oracle information injection** as the main analysis tool, rather than designing adversarial conversational pressures or user-behavior manipulations.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO targets *conversation-specific* degradation (e.g., belief/stance drift, social pressure), it is closer to real dialogue phenomena than synthetic game environments.
- GALILEO can emphasize **interaction protocols** that resemble user/assistant exchanges rather than action APIs.

## Where GALILEO is weaker / needs to improve

- If GALILEO lacks ablations that attribute failures to specific causes, LUMINA’s **oracle counterfactual framing** is a useful template.
