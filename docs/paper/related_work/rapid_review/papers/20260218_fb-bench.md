# FB-Bench: A Fine-Grained Multi-Task Benchmark for Evaluating LLMs’ Responsiveness to Human Feedback

- Year: 2024
- Venue: arXiv
- Authors: Youquan Li; Miao Zheng; Fan Yang; Guosheng Dong; Bin Cui; Weipeng Chen; Zenan Zhou; Wentao Zhang
- URL: https://arxiv.org/abs/2410.09412
- BibTeX key (if we add it): FBbench2024Li
- Tags: benchmark, multi-turn, human-feedback, responsiveness, evaluation, chinese

## One-sentence takeaway

FB-Bench is a Chinese multi-turn benchmark (591 samples) that measures whether LLMs properly *use* user feedback to correct errors or *resist* misleading feedback to maintain correct answers, using a weighted-checklist + LLM-judge protocol.

## What problem does it solve?

- Existing LLM benchmarks often focus on single-turn QA or multi-turn chats where turns are independent, missing the real-world dynamic where users react to *the model’s previous response*.
- There is no systematic, fine-grained way to evaluate “responsiveness to feedback” across multiple tasks and feedback styles (helpful hints vs misinformation vs credibility challenges, etc.).

## What is the core method / protocol?

- Define two core interaction scenarios:
  - **Error correction (EC):** prior model response is wrong/deficient; user feedback should help the model improve.
  - **Response maintenance (RM):** prior model response is correct; user feedback may challenge it; model should *maintain* the correct stance.
- Build a **three-tier taxonomy** spanning:
  - 8 query task types (math, reasoning, coding, extraction, error correction, creation, knowledge QA, translation)
  - 5 deficiency types for prior responses (not following instructions, logical errors, incomplete answers, factual errors, unprofessional answers)
  - 9 feedback types (incl. hinting guidance; pointing out errors; clarifying intent; raising objections; detailed explanation requests; and RM-oriented misleading feedback like misinformation / fabricated credentials / unreasonable requests)
- Dataset: **591 curated samples** in Chinese; each includes user query, preset model response, human feedback, and a **sample-specific checklist** (with weights for EC).
- Scoring: generate a follow-up response from the tested model, then use **GPT-4o as judge** to score against the checklist.
  - EC: weighted partial credit across checklist items.
  - RM: “all criteria met” binary credit (must maintain correct stance).
- They report human–judge agreement **> 90%** (as claimed in the paper) to support robustness.

## What are the key metrics?

- Primary: checklist-based score of the model’s follow-up response after feedback.
  - Weighted score in EC.
  - Binary success in RM.
- Secondary analyses: performance sliced by task type, feedback type, and deficiency type.

## What are the main results?

- Large variation across models in responsiveness depending on scenario (EC vs RM) and feedback type.
- Claim: open-source vs closed-source gaps are narrowing; open-source models appear stronger in **response maintenance**.
- Feedback type matters: “hinting guidance” helps; “misinformation” / “credibility support” can mislead models.
- Stronger models better fix all deficiency categories, especially logical errors and instruction-following failures.

## How is this similar to GALILEO?

- If GALILEO cares about **multi-turn interaction quality** and **using human feedback**, FB-Bench provides:
  - A clean decomposition into “correct when corrected” vs “don’t get swayed when already correct”.
  - A taxonomy of feedback styles that can map onto GALILEO’s interaction/evaluation dimensions.
- The “RM under adversarial user feedback” angle is conceptually close to robustness/safety-style evaluations.

## How is this different from GALILEO?

- FB-Bench is primarily an **evaluation benchmark** (curated dataset + scoring protocol), not a training method.
- Focused on **Chinese** real-world feedback patterns; may not generalize directly to other languages/domains.
- Relies on an **LLM-as-judge** (GPT-4o) plus checklists, rather than purely human evaluation or task-grounded automatic metrics.

## Where GALILEO is stronger / cleaner (if true)

- If GALILEO uses task-grounded or externally verifiable objectives, that can be cleaner than judge-based scoring.
- If GALILEO covers broader domains, languages, or includes tool use / long-horizon interaction, it may exceed FB-Bench’s scope.

## Where GALILEO is weaker / needs to improve

- If GALILEO currently lacks explicit evaluation for **response maintenance under misleading feedback**, FB-Bench highlights a gap.
- If GALILEO lacks a fine-grained feedback taxonomy, FB-Bench’s categories could improve analyses and ablations.

## Action items for GALILEO (experiments / method / writing)

- [ ] Add an evaluation slice that separates **error-correction** vs **response-maintenance** scenarios.
- [ ] Explicitly test robustness to “RM adversarial” feedback types (misinformation, fabricated authority).
- [ ] Consider adopting a **checklist-based rubric** for certain interactive tasks; measure human–judge agreement if using LLM judges.
- [ ] Cite FB-Bench when motivating why single-turn or turn-independent multi-turn benchmarks miss real feedback dynamics.
